### 二、`pipeline/run_preprocessing.py` 重构——消除硬编码路径

**变更前的问题**：
- 路径硬编码为 `ROOT_DIR = Path("/mnt/hdd/private/gyw/Code/txbb/Single_cell_train")`，强绑定服务器环境
- `CHC20`、`CHC23` 切片名写死在代码里，切换数据集需要修改多处
- 函数 `_compare_slices()` 内部硬编码了 "CHC20"/"CHC23" 标签

**变更后**：
1. **动态路径**：改为 `_REPO_ROOT = Path(__file__).resolve().parents[2]`，通过脚本自身位置推断项目根目录，无需修改
2. **`main()` 参数化**：新增参数 `path_sample1`, `path_sample2`, `sample1_name`, `sample2_name`, `output_dir`，不同数据集通过传参切换
3. **通用对比函数**：将 `_compare_slices()` 重命名并改写为 `_compare_slices_generic(prop_s1, prop_s2, name1, name2, ...)`，支持任意切片名称
4. **验证切片可选**：`path_sample2=None` 时自动跳过 Step 7/8，支持单样本运行

**核心改动代码（主函数签名）**：
```python
def main(
    path_scrna: Path = PATH_SCRNA_H5AD,
    path_sample1: Path = PATH_SAMPLE1,
    path_sample2: Path | None = PATH_SAMPLE2,

    sample2_name: str = SAMPLE2_NAME,   # 如 "CHC23" / "HCC6NR"
    output_dir: Path = OUTPUT_DIR,
):
```

### 三、三个数据集入口脚本

新增三个入口脚本，每个只需运行一条命令即可完成数据集的全部分析：

| 脚本 | 数据集 | 输出目录 |
|---|---|---|
| `code/run_chc20.py` | CHC20（含 CHC23 配对验证） | `results/CHC20/` |
| `code/run_hcc4r.py` | HCC4R（含 HCC6NR 配对验证） | `results/HCC4R/` |
| `code/run_hcc6nr.py` | HCC6NR（含 HCC4R 配对验证） | `results/HCC6NR/` |

**每个入口脚本的设计特点**：
- 只需修改脚本顶部的 `PATH_SAMPLE1` / `PATH_SAMPLE2` 路径常量即可适配不同服务器
- 支持 `--step1-only` / `--step2-only` / `--no-sample2` 三个命令行参数
- Step 2 通过 `subprocess` 调用 `pipeline/run_spatial_niche_analysis.py`，保留完整的参数灵活性

**运行示例**：
```bash
# 运行 HCC4R 完整流程（Step 1 + Step 2）
python code/run_hcc4r.py

# 仅运行 HCC4R 的空间生态位分析（已有反卷积结果时）
python code/run_hcc4r.py --step2-only

# 跳过配对验证切片（单样本模式）
python code/run_hcc4r.py --no-sample2
```

### 五、`pipeline/run_spatial_niche_analysis.py` 的前期修改（保留记录）

以下为上一轮修改的内容，本次一并保留在此记录：

#### 5.1 Step 15 参数扫描修复（resolution → k）

**根本问题**：原始扫描使用 `resolution × quantile` 二维网格，但 Leiden `resolution` 仅决定聚类粒度，**不影响 `niche_score` 数值**，导致所有列 DEG 结果完全相同，热图无意义。

**修复方案**：改为 `k × quantile` 扫描，`k`（kNN 邻居数）直接影响邻域组成向量，进而影响 `niche_score` 和 DEG 结果：
- 横轴：`niche_high_quantile`（0.70 / 0.75 / 0.80 / 0.85）
- 纵轴：`k`（8 / 10 / 15 / 20 / 25）
- 颜色：FDR<0.05 且 log2FC>0.5 的 DEG 数量
- 选参标准：颜色最深且处于"高原"区域（与相邻格子结果相近）的参数组合为推荐

**代码改动**：
```python
# 原：
# resolution_list=(0.3, 0.4, 0.5, 0.6, 0.7)
# pivot = param_scan_df.pivot(index="resolution", ...)

# 改为：
k_list=(8, 10, 15, 20, 25)
pivot = param_scan_df.pivot(index="k", columns="quantile", values="n_sig_deg")
ax.set_ylabel("kNN neighbors (k)")
```

#### 5.2 Gini Index 文件生成保障

**问题**：`gini > 0.5` 阈值过严，FOXP3 等稀有基因（Gini ≈ 0.3~0.5）被过滤，且文件仅在结果非空时保存。

**修复**：
1. 阈值从 0.5 降至 **0.3**
2. **始终写出** `gini_score_genes.csv`（即使空文件也写出，保证路径可预期）

```python
# 原：
if gini > 0.5: ...
if not gini_df.empty:
    gini_df.to_csv(...)

# 改为：
if gini > 0.3: ...
gini_df = ranked.attrs.get("gini_df", pd.DataFrame(
    columns=["gene", "gini", "log2_fc", "mean_high"]
))
gini_df.to_csv(gini_out, index=False)  # 始终写出
```
